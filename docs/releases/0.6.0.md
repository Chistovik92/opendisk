# OpenDisk 0.6.0 — файловый менеджер как в проводниках, одинаковый на обоих телефонах

Главное в выпуске — телефоны: файловый менеджер переделан, и на Android, и на
iPhone он теперь один и тот же. Кроме того — скорость и недавние файлы в трее,
проверка устойчивости десктопа, «Войти заново» на телефонах и чтение больших
файлов кусками на Android.

## Телефоны: Android и iPhone

- **Главный экран.** Карточки хранилищ с полосой заполнения, шесть категорий
  («Изображения», «Видео», «Звук», «Документы», «Загрузки», «Новые» — файлы
  из всех папок одним списком), закладки на папки любого диска, облака.
  На iPhone категории собираются по папке OpenDisk: чужие файлы песочница не
  отдаёт.
- **Папка.** Путь ступенями — нажатие на ступень открывает эту папку. Три
  вида списка (короткий, подробный, плитки), миниатюры картинок, сортировка
  по имени, размеру, дате и типу, скрытые файлы, поиск по имени, кнопка «+»
  для новой папки и файла.
- **Выбор нескольких файлов.** Долгое нажатие включает выбор, ещё одно
  долгое — отмечает всё от прошлого отмеченного (диапазон). Внизу: копировать,
  вырезать, удалить, отправить, ещё (переименовать, свойства, ссылка,
  скачать, распаковать zip, сжать в zip).
- **Файлы больше не затираются.** Вставка в папку, где уже есть файл с таким
  именем, раньше молча перезаписывала его; теперь копия получает «(2)».
  Переименование в занятое имя отказывает с сообщением.
- Контракт интерфейса — [docs/MOBILE-UI.md](https://github.com/Chistovik92/opendisk/blob/main/docs/MOBILE-UI.md):
  чтобы не искать кнопки, пересев с одного телефона на другой.

## Облака на телефонах

- **«Войти заново».** В «⋮» у облака и на экране ошибки папки. Имя и настройки
  остаются, меняется токен. Облако с истёкшим доступом помечено «Нужно войти
  заново» — вместо того чтобы удалять и добавлять его с потерей настроек.
- **Токены не протухают от простоя.** Раз в сутки приложение само обращается
  к каждому облаку (на iPhone — когда iOS позволит). Google в режиме
  тестирования это не лечит: токен там умирает через неделю в любом случае.
- **Android: возврат из браузера.** После входа через браузер приложение само
  выходит на передний план.
- **Android: большие файлы открываются сразу.** Видео и крупные файлы из облака
  читаются кусками, а не скачиваются целиком перед показом. Для этого в
  библиотеку rclone на телефоне подключён HTTP-сервер, закрытый случайным
  паролем.

## Компьютер

- **Скорость в трее.** В подсказке значка — с какой скоростью приложение
  передаёт данные прямо сейчас (не объём, а скорость). В меню трея —
  «Недавно синхронизировано»: последние восемь файлов, нажатие открывает папку.
  Выключается в настройках.
- **Проверка устойчивости.**
  - rclone запускался без пароля на локальном порту — команды ему мог слать
    любой на машине. Теперь у каждого запуска случайный пароль.
  - Настройки писались на месте: обрыв посреди записи стирал настройки всех
    облаков. Теперь запись атомарная, испорченный файл откладывается в
    `.broken`, одновременные правки не затирают друг друга.
  - На машине с несколькими пользователями второй пользователь не мог
    запустить OpenDisk: замок единственного экземпляра был общий.
  - При перезапуске rclone не отвечавший процесс оставался жить, и их
    становилось всё больше.
  - Подключение и отключение диска: любой сбой снимает «крутилку», а не
    только ответ rclone.
  - Автозапуск: зависший PowerShell подвешивал приложение; путь AppImage с
    пробелом ломал автозапуск на Linux.
- **Установщик на Windows меньше на 15%:** 90,4 → 76,9 МБ.

## Что не вошло

- **File Provider на iPhone** — облака в приложении «Файлы». Нужны платная
  подпись Apple и Mac для проверки; в неподписанной сборке недоступно.
- **macOS и Android-обновление на живых устройствах** по-прежнему проверены
  хуже остального: Mac и телефона для проверки в CI нет.
- iPhone: Swift пока проверен тестами логики и сборкой, но не глазами.
