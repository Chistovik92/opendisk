# Дорожная карта OpenDisk

Открытый кроссплатформенный клиент виртуальных облачных дисков (аналог Disk-O / Air Explorer),
без подписок, на движке [rclone](https://rclone.org/) с собственным GUI.

Реализацию ведёт Claude по запросам [[SecretHero]](https://github.com/Chistovik92) —
каждый этап оформляется отдельными PR/коммитами с рабочим кодом, а не только описанием.

## Принцип архитектуры

Диски выглядят как обычные физические (буква диска в Windows, том в Finder, папка в
файловом менеджере Linux, источник в «Файлах» на Android/iOS), но полностью виртуальны:
содержимое не хранится на устройстве, а подгружается по требованию из облака.

Десктоп и мобильные платформы устроены принципиально по-разному — у Android/iOS нет
доступа к FUSE/WinFsp без root/jailbreak, вместо этого у них есть свои официальные
API именно для облачных дисков. Поэтому архитектура состоит из общего ядра и разных
"обвязок" под каждую платформу:

```
                         ┌──────────────────────────┐
                         │      rclone (Go)           │  общее ядро для ВСЕХ платформ:
                         │  протоколы облаков, OAuth,  │  протоколы, кэш, шифрование —
                         │  кэш, шифрование            │  ничего не пишем заново
                         └─────────────┬────────────┘
                                       │
            ┌──────────────────────────┼──────────────────────────┐
            │ Десктоп (Win/Linux/macOS) │      Мобильные (Android/iOS)          │
            │ rclone rcd как процесс,   │      rclone-core собран как           │
            │ GUI общается по HTTP RC   │      библиотека через gomobile        │
            │ API                        │      (.aar / .framework)              │
            └──────────────┬────────────┘      └──────────────┬─────────────────┘
                           │                                    │
        ┌──────────────────▼──────────────────┐   ┌────────────▼─────────────────┐
        │  Виртуальная ФС уровня ОС             │   │  Официальный API облачных     │
        │  Linux: FUSE                           │   │  дисков платформы              │
        │  macOS: macFUSE                        │   │  Android: DocumentsProvider    │
        │  Windows: WinFsp                       │   │  iOS: File Provider Extension  │
        │  → виден ЛЮБОМУ приложению в ОС        │   │  → виден в «Файлах», доступен   │
        │                                         │   │    приложениям через системный │
        │                                         │   │    диалог выбора файла         │
        └─────────────────────────────────────────┘   └─────────────────────────────────┘
```

**Важное отличие мобильных платформ:** на десктопе диск монтируется как настоящая
папка, видимая абсолютно всем программам. На Android/iOS так низкоуровнево работать
запрещено самой ОС — вместо этого используется официальный, предназначенный именно
для облачных дисков механизм (так же устроены официальные клиенты Google Drive и
Dropbox на телефонах). Внешне для пользователя разница минимальна — диск так же
виден в «Файлах» с on-demand загрузкой, — но интеграция с произвольными приложениями
идёт не напрямую через ФС, а через системный диалог выбора файлов.

Мы нигде не переизобретаем протоколы облаков и монтирование — за это отвечает rclone
(70+ провайдеров, включая Яндекс.Диск, Mail.ru через WebDAV, Google Drive, S3, Dropbox)
на всех платформах одновременно. Наша задача — GUI/нативная обвязка под каждую ОС,
автозапуск, трей, профили, кэш-политики.

## Этап 1 — Ядро: обёртка над rclone RC API (2-3 недели)

- [x] Встроенный rclone: бинарник едет внутри дистрибутива (скачивается на этапе сборки
      с проверкой SHA-256), пользователю ставить его отдельно не нужно — см. docs/ARCHITECTURE.md
- [x] Модуль `rclone-bridge`: запуск/остановка процесса `rclone rcd` из Kotlin (`ProcessBuilder`),
      с ожиданием готовности порта и перехватом вывода
- [x] Kotlin-клиент HTTP для RC API (Ktor client): методы
  - `config/create`, `config/get`, `config/listremotes`, `config/delete` — управление облаками
  - `mount/mount`, `mount/unmount`, `mount/listmounts` — монтирование
  - `core/stats`, `job/status` — прогресс операций
- [x] Хранение конфигурации облаков — используем родной `rclone.conf` (шифруемый паролем rclone),
      не изобретаем свой формат: поиск пути по правилам rclone, определение шифрования,
      передача пароля через окружение
- [x] Юнит-тесты на обёртку (мокаем HTTP-ответы) + интеграционный тест против настоящего rcd

**Результат:** консольная утилита на Kotlin, которая умеет добавить облако (Яндекс.Диск, WebDAV)
и смонтировать его в папку — без всякого GUI, только для проверки ядра.

## Этап 3 — Монтирование по платформам "по-нативному" (2-3 недели)

**Результат:** пользователь без консоли видит диск в проводнике/файловом менеджере, файлы
подгружаются по требованию.

## Этап 6 — Android-клиент (4-5 недель, после стабилизации десктопа)

- [ ] Сборка `rclone` под Android через `gomobile bind` → `.aar`-библиотека
      (переиспользуем то же ядро, что и на десктопе — протоколы, OAuth, кэш)
- [ ] Реализация `DocumentsProvider` (Storage Access Framework) — это официальный
      Android-API именно для облачных дисков, так же работают Google Drive/Dropbox
- [ ] Диск появляется в системном приложении «Файлы» и доступен любому приложению
      через стандартный диалог выбора файла
- [ ] UI на Kotlin/Compose (переиспользуем опыт и часть кода с [[hydra]] и [[neurocode-android]])
- [ ] Фоновая синхронизация через `WorkManager`, кэш on-demand при открытии файла

**Ограничение платформы:** в отличие от десктопа, диск не будет виден как "обычная
папка" абсолютно всем программам напрямую — это системное ограничение Android без
root, а не недоработка. Взаимодействие идёт через системный провайдер документов.

## Этап 7 — iOS-клиент (4-5 недель, после Android)

- [ ] Сборка `rclone` под iOS через `gomobile bind` → `.framework`
- [ ] Реализация **File Provider Extension** — официальный Apple API для облачных
      дисков (так работают Dropbox, OneDrive, iCloud Drive на iPhone/iPad)
- [ ] Диск появляется в приложении «Файлы» рядом с iCloud Drive, с on-demand
      загрузкой и миниатюрами
- [ ] UI на SwiftUI (либо Compose Multiplatform, если к этому моменту его iOS-таргет
      будет достаточно зрелым — решаем по факту на момент старта этапа)

**Ограничение платформы:** так же как и на Android, прямого доступа к произвольной
виртуальной ФС Apple не даёт — File Provider Extension это официальный и единственный
легальный путь для сторонних облачных дисков на iOS.

## Оценка сроков

- Десктоп MVP (этапы 0-3, Linux+Windows с GUI) — **≈ 8-10 недель**
- Полный десктоп-релиз (+ этапы 4-5, macOS, упаковка) — **≈ +4-5 недель**
- Android-клиент (этап 6) — **≈ +4-5 недель**
- iOS-клиент (этап 7) — **≈ +4-5 недель**

Итого до покрытия всех пяти платформ (Windows, Linux, macOS, Android, iOS) — ориентировочно
**≈ 20-24 недели** при последовательной работе итерациями через чат с Claude (по одному
этапу/модулю за раз, с проверкой и правками между шагами). Десктоп и мобильные этапы можно
вести параллельно, если подключится больше ресурсов, но по умолчанию план — последовательный.
