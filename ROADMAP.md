# Дорожная карта OpenDisk

Открытый кроссплатформенный клиент виртуальных облачных дисков (аналог Disk-O / Air Explorer),
без подписок, на движке [rclone](https://rclone.org/) с собственным GUI.

Реализацию ведёт Claude по запросам [[SecretHero]](https://github.com/Chistovik92) —
каждый этап оформляется отдельными PR/коммитами с рабочим кодом, а не только описанием.

## Принцип архитектуры

Диски выглядят как обычные физические (буква диска в Windows, том в Finder, папка в
файловом менеджере Linux, источник в «Файлах» на Android/iOS), но полностью виртуальны:
содержимое не хранится на устройстве, а подгружается по требованию из облака.

Десктоп и мобильные платформы устроены принципиально по-разному — у Android/iOS нет
доступа к FUSE/WinFsp без root/jailbreak, вместо этого у них есть свои официальные
API именно для облачных дисков. Поэтому архитектура состоит из общего ядра и разных
"обвязок" под каждую платформу:

```
                         ┌──────────────────────────┐
                         │      rclone (Go)           │  общее ядро для ВСЕХ платформ:
                         │  протоколы облаков, OAuth,  │  протоколы, кэш, шифрование —
                         │  кэш, шифрование            │  ничего не пишем заново
                         └─────────────┬────────────┘
                                       │
            ┌──────────────────────────┼──────────────────────────┐
            │ Десктоп (Win/Linux/macOS) │      Мобильные (Android/iOS)          │
            │ rclone rcd как процесс,   │      rclone-core собран как           │
            │ GUI общается по HTTP RC   │      библиотека через gomobile        │
            │ API                        │      (.aar / .framework)              │
            └──────────────┬────────────┘      └──────────────┬─────────────────┘
                           │                                    │
        ┌──────────────────▼──────────────────┐   ┌────────────▼─────────────────┐
        │  Виртуальная ФС уровня ОС             │   │  Официальный API облачных     │
        │  Linux: FUSE                           │   │  дисков платформы              │
        │  macOS: macFUSE                        │   │  Android: DocumentsProvider    │
        │  Windows: WinFsp                       │   │  iOS: File Provider Extension  │
        │  → виден ЛЮБОМУ приложению в ОС        │   │  → виден в «Файлах», доступен   │
        │                                         │   │    приложениям через системный │
        │                                         │   │    диалог выбора файла         │
        └─────────────────────────────────────────┘   └─────────────────────────────────┘
```

**Важное отличие мобильных платформ:** на десктопе диск монтируется как настоящая
папка, видимая абсолютно всем программам. На Android/iOS так низкоуровнево работать
запрещено самой ОС — вместо этого используется официальный, предназначенный именно
для облачных дисков механизм (так же устроены официальные клиенты Google Drive и
Dropbox на телефонах). Внешне для пользователя разница минимальна — диск так же
виден в «Файлах» с on-demand загрузкой, — но интеграция с произвольными приложениями
идёт не напрямую через ФС, а через системный диалог выбора файлов.

Мы нигде не переизобретаем протоколы облаков и монтирование — за это отвечает rclone
(70+ провайдеров, включая Яндекс.Диск, Mail.ru через WebDAV, Google Drive, S3, Dropbox)
на всех платформах одновременно. Наша задача — GUI/нативная обвязка под каждую ОС,
автозапуск, трей, профили, кэш-политики.

## Как читать эту карту

Раньше она была разбита на «этапы» — от них пришлось отказаться: этапы шли не по
порядку, а версии выходили чаще, чем закрывались этапы. Теперь всё по версиям
приложения, и это заодно отвечает на вопрос «что уже можно поставить».

Сделанное описано коротко: подробности каждого выпуска —
на [странице релизов](https://github.com/Chistovik92/opendisk/releases).
Незакрытые пункты сгруппированы по будущим версиям; сроки не проставлены
намеренно, порядок важнее дат.

## Выпущено

### 0.1.x — рабочий десктоп

Ядро и интерфейс. К концу ветки приложение делало всё, ради чего затевалось.

- **Ядро** `rclone-bridge`: запуск и остановка `rclone rcd`, типизированная
  обёртка над RC API, разбор ошибок rclone в человеческий текст.
- **Встроенный rclone**: едет внутри дистрибутива, скачивается при сборке
  и сверяется по SHA-256. Отдельно ставить ничего не нужно.
- **Интерфейс** на Compose Multiplatform: список облаков, мастер добавления,
  подключение диском, занятое место, трей, уведомления.
- **Плитки популярных сервисов** вместо списка из семи десятков бэкендов;
  полный список остался за «другим подключением».
- **Монтирование**: WinFsp едет в дистрибутиве Windows и ставится по кнопке;
  на Linux `fuse3` прописан в зависимостях пакета.
- **Режимы кэша** — ответ на главный вопрос «скачивать всё или по требованию».
- **Автозапуск, автоподключение, ограничение скорости, русский и английский.**
- **Упаковка**: MSI (свой установщик на WiX — jpackage не умеет закрывать
  работающее приложение), DEB, RPM, AppImage, DMG; сборка в CI на трёх ОС.
- **Установка на Linux одной командой** скриптом с GitHub.
- **Окно «О приложении»**, руководство пользователя, страница проекта.

### 0.2.x — то, что вскрылось при реальной эксплуатации

Ветка целиком состоит из починок, и почти каждая нашлась не по коду, а по жалобе
или замеру на живой системе.

- **0.2.5** — обновление из приложения со сверкой контрольной суммы; уборка
  за собой при удалении, с отдельным спросом про конфиг облаков и WinFsp.
- **0.2.6** — диски на Windows стали сетевыми: как обычные локальные они
  заставляли систему их индексировать, и медленное облако подвешивало
  проводник целиком. Предупреждение про общий идентификатор Google:
  замер на живом диске дал 33 секунды на список из 65 файлов против одной
  секунды у Яндекса.
- **0.2.7** — неверный идентификатор Google ловится до похода в браузер;
  из ожидания подтверждения можно выйти.
- **0.2.8** — поле подключения можно очистить. Без этого нельзя было уйти
  с удалённых учётных данных Google.
- **0.2.9** — rpm собирался неправильно: встроенный rclone был неисполняемым,
  ярлык пропадал после каждого обновления, работающая копия не закрывалась.

Кроме того, в эту же ветку попали починки, каждая из которых была настоящей
поломкой: автозапуск не работал ни в одной версии; на Linux не создавался
каталог точки монтирования; осиротевший rclone после аварийного завершения
держал диски.

### 0.6 — Android

Ядро уже собрано и проверено: `librclone` собирается в CI, инструментальные
тесты гоняются на эмуляторе, транспорт вынесен отдельным слоем — разбор
ответов RC API общий с десктопом.

- [x] Сборка `rclone` под Android через `gomobile bind`.
- [x] Транспорт поверх librclone, общий разбор ответов с десктопом.
- [ ] `DocumentsProvider` — официальный и единственный путь для облачных
      дисков на Android. Диск появляется в системном «Файлы».
- [ ] Интерфейс на Compose, общий по духу с десктопным.
- [ ] Фоновая работа через `WorkManager`, кэш по требованию.
- [ ] Раздача с учётом размера: библиотека 56 МБ на архитектуру, поэтому

программе как папка. Android без root такого не позволяет никому, включая
официальные клиенты Google Drive и Dropbox.

## Потом

- Шифрование содержимого на лету — у rclone это готовый бэкенд `crypt`.
- Синхронизация по расписанию, а не только монтирование по требованию.
- Общий слой бизнес-логики между десктопом и Android. Сейчас общий только
  разбор ответов RC API; объединять остальное имеет смысл после того,
  как оба таргета устоятся.
- Плагины для бэкендов, которых нет в rclone.

## Чего в карте нет намеренно

- **32-битные сборки.** Движок отрисовки под x86 не выпускается, а 32-битных
  JDK новее восьмой версии не существует.
- **Свой протокол или свой клиент облаков.** Всё это делает rclone, и делает
  лучше, чем получилось бы у нас.
- **Сроки.** Порядок важнее: каждый выпуск этой ветки появлялся из того,
  что нашлось при использовании, а не из плана.
