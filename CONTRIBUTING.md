# Участие в разработке

Проект в ранней стадии, структура и API могут меняться между этапами дорожной карты
(см. [ROADMAP.md](ROADMAP.md)).

## Порядок работы

1. Проверь [ROADMAP.md](ROADMAP.md) — какой этап сейчас активен, чтобы не делать
   работу "из будущего" (например, упаковку под macOS до готового MVP на Linux/Windows).
2. Заведи Issue с описанием, что предлагаешь сделать, если это не мелкая правка.
3. Форкни репозиторий, создай ветку `feature/<короткое-имя>`.
4. Коммиты — осмысленные, по-русски или по-английски, главное понятно.
5. Открой Pull Request, опиши, что изменилось и как проверить.

## Стиль кода

- Kotlin — официальный [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html)
- Форматирование — `ktlint` (будет подключен на Этапе 1)
- Не добавляем новые зависимости без необходимости — проект должен оставаться лёгким

## Тестирование

- Модуль `rclone-bridge` должен иметь юнит-тесты на обёртку HTTP-вызовов
  (без реального запуска rclone — мокаем ответы)
- GUI-изменения — ручная проверка на Linux обязательна перед PR (это основная
  платформа разработки на старте)
