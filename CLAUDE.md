# Заметки для Claude Code

Этот файл читает Claude Code на любой машине, где открыт репозиторий. Здесь —
то, что не видно из кода и истории: как выпускается проект, на чём уже
обжигались и как владелец проекта предпочитает работать. Секретов (ключи,
пароли, токены) здесь нет и быть не должно.

Что делает проект и куда движется — [ROADMAP.md](ROADMAP.md),
устройство — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Как работать с владельцем проекта

- Общение, коммиты, комментарии в коде и документация — по-русски.
  Комментарии объясняют «почему», подробно, в стиле уже существующих.
- Не хватает программы, SDK или файла (JDK 17, Android SDK, эмулятор…) —
  спросить сразу, одним списком с размерами и источниками, а не обходить
  молча и не оставлять непроверенным.
- Android TV владелец проверяет дома на настоящих телевизорах — эмуляторы ТВ
  не нужны. Для проверки собрать apk и дать чек-лист.
- Коммиты — по логическим частям, заголовок по-русски о том, что изменилось
  для человека (см. `git log`).

## Выпуск версии

1. Номер — в `build.gradle.kts` (`version`) и `composeApp/build.gradle.kts`
   (`packageVersion`). `.dmg` получает `1.<минор>.<патч>` сам: macOS не
   принимает версию бандла с нулём в начале — это не ошибка.
2. Заметки — `docs/releases/<версия>.md`, первая строка `# OpenDisk X — …`
   становится названием выпуска. Таблицу «что качать» собирает
   `scripts/release-notes.sh`. Пользовательская документация — `docs/USAGE.md`,
   `README.md`; план — `ROADMAP.md`.
3. Проверка без публикации: `gh workflow run release.yml --ref <ветка>` —
   собирает все платформы и ставит установщики на настоящие Windows и Linux,
   но релиз не создаёт (публикация только по тегу).
4. Выпуск: `main` на проверенный коммит, тег `v<версия>`, push тега —
   `release.yml` пересобирает, перепроверяет и публикует. Выпуски 0.x
   публикуются как prerelease намеренно.

`android.yml` запускается сам на push в `android-*`/`rclone-bridge` и гоняет
инструментальные тесты на эмуляторе (Android 10). Обычные JVM-тесты модуля
`android-app` (`src/test`) он не запускает.

## Windows-установщик (composeApp/wix/Product.wxs) — на чём обжигались

- **0.5.8 ломал установку при обновлении поверх работающего OpenDisk.**
  Закрытие приложения шло после снятия старой версии; занятые jar Windows
  удаляла после перезагрузки — уже новые файлы с теми же именами. Приложение
  после перезагрузки не запускалось. Исправлено в 0.5.9: действие
  `StopOpenDisk` до `InstallValidate`.
- **В 64-битном MSI `[SystemFolder]` — это SysWOW64.** 32-битный PowerShell
  не видит путей 64-битных процессов (`Process.Path` пустой). Для кода,
  которому нужны процессы, — `[System64Folder]` и `Win32_Process.ExecutablePath`.
- **В `ExeCommand` нельзя квадратные скобки в коде PowerShell** — MSI считает
  их ссылкой на свойство и подставляет пустую строку
  (`[StringComparison]::…` ломается).
- **Уборка `--cleanup` — только при настоящем удалении**
  (`REMOVE="ALL" AND NOT UPGRADINGPRODUCTCODE`). До 0.5.8 включительно она
  шла и при обновлении и стирала `%APPDATA%\opendisk` и автозапуск; старые
  установщики уже у людей, поэтому новый сохраняет настройки до снятия старой
  версии (`BackupUserSettings`/`RestoreUserSettings`).
- Проверка `verify-windows` в `release.yml` проходит сценарий
  `x64-over-running` — новый `.exe` поверх работающей копии прошлой версии.
  Именно он поймал обе ошибки выше; обычный путь обновления через само
  приложение их не видит (оно закрывается до запуска установщика).

**Разбор, если OpenDisk на Windows не запускается:**
- `C:\Program Files\OpenDisk\app\OpenDisk.cfg` — все ли jar из `app.classpath`
  на месте;
- журналы установщика — `%TEMP%\OpenDisk_*.log` (Burn) и
  `…_000_OpenDiskMsi.log` (MSI, в UTF-16); при провале проверки в CI они
  лежат в артефакте `verify-windows-*-screenshots`;
- журнал событий «Приложение», источник `MsiInstaller` — коды 1029/1038
  значат, что файлы были заняты и что-то ждёт перезагрузки;
- `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\PendingFileRenameOperations`.
- Починка на месте: поставить текущий `.exe` поверх или
  `msiexec /fa "C:\ProgramData\Package Cache\{…}v<версия>\OpenDisk-<версия>.msi"`.

## Android

- `librclone` берётся из релиза `librclone-v<версия>[-<ревизия>]` по SHA-256
  (`android-core/build.gradle.kts`). Ревизия `r2` — с 32-битной ARM
  (armeabi-v7a) для приставок Android TV и часов Wear OS. Пересборка —
  workflow «librclone для Android» с `revision=rN`, затем обновить ревизию и
  сумму. В выпуске apk: `-arm64`, `-arm32`, `-universal`.
- Поставщик документов (`OpenDiskDocumentsProvider`) с 0.5.9 на запись:
  файл, открытый на запись, пишется в `cacheDir/uploads` и уходит в облако
  при закрытии; не ушедший досылается при следующем обращении. Идентификатор
  документа `облако/путь` хранится системой — формат не менять.
- Подпись apk — только в CI, постоянным ключом из секретов
  (`ANDROID_KEYSTORE_BASE64` и др.); CI сверяет отпечаток сертификата.
  На машины разработки ключ не переносим. Для локальных сборок, которые
  нужно поставить рядом с настоящим OpenDisk, — отдельный applicationId
  отладочной сборки (ещё не сделано).

  Пока их нет, собирать и проверять — через CI.
